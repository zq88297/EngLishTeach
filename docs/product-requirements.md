# EnglishTech 产品需求文档

> 版本：MVP v1
> 更新日期：2026-07-24
> 状态：实现基线
> 上位定义：PRODUCT.md
> 决策来源：docs/requirements-decision-log.md

## 1. 背景与目标

EnglishTech 面向 16 岁及以上的中国雅思学习者，将词汇、听力和阅读训练嵌入俯视角悬疑冒险。MVP 提供两宗各七章的原创案件，通过七次建议学习会话完成诊断、学习、复习和综合结案。

产品必须同时满足两个目标：

1. 用户愿意因为案件进展继续完成学习会话。
2. 系统能够用可靠证据衡量词汇义项、听力理解和阅读理解的变化。

剧情成败与学习掌握度是两个独立状态域。剧情失败可以改变案件状态，但不得删除学习记录，也不得把超时、设备故障或辅助操作需求作为知识错误。

## 2. 用户与核心路径

### 2.1 目标用户

- 16 岁及以上、中文为主要界面语言的雅思学习者。
- 当前能力主要位于雅思 5.0-6.5，MVP 内容目标为训练 5.5-6.5 难度范围内的词汇、听力和阅读能力。
- 主要在手机或电脑上进行 10-15 分钟的短时学习。

产品不得展示官方雅思分数预测，也不得承诺确定提分。

### 2.2 核心路径

1. 用户确认年龄、阅读隐私说明并注册或登录。
2. 用户完成 8-12 分钟的初始诊断，或明确跳过并从标准难度开始。
3. 用户主动选择一宗案件，开始第一章。
4. 每章完成探索、词汇、听力、阅读和剧情决策。
5. 到期复习优先进入下一章的自然场景；无法嵌入时进入总部复盘任务。
6. 用户完成七章后进入综合结案，并在新语境中完成延迟测试。
7. 用户可以切换案件；案件进度独立，学习项目的掌握记录共享。

## 3. 范围与非目标

### 3.1 MVP 范围

- 两宗原创案件：宫廷权谋悬疑、都市轻度惊悚，各七章。
- 词汇、听力和阅读三类学习活动。
- 确定性推荐、FSRS 复习调度、作者预写解析和陷阱。
- 邮箱账号、跨设备同步和可安装 PWA。
- 调查总部提供案件入口、证物陈列和三档里程碑成长。
- 中文界面、英文学习材料、固定发布的预生成音频。

### 3.2 非目标

- 不包含口语、写作、官方模考评分、排行榜、社交、公会或实时对战。
- 不包含支付、广告、付费体力、连续签到惩罚或生成式 AI。
- 不建设内容管理后台；内容通过版本化文件发布。
- MVP 不承诺两宗案件完成后持续提供新剧情。完成后的长期能力仅包括到期复习、案件回顾和总部陈列。

## 4. 学习内容规格

### 4.1 学习项目标识

每个词汇学习项目必须以稳定的 lexemeId 和 senseId 唯一标识，不得只用展示单词作为主键。学习项目至少包含：

- 词元、目标义项、词性和雅思难度标签。
- 中文释义、英文定义、例句和常见搭配。
- acceptedForms：允许提交的词形、固定短语和明确同义表达。
- confusableIds：经过作者审校的易混项目。
- 至少一条正确解析和每个陷阱对应的错误解析。

同一词元的不同义项分别计算掌握度。同一学习项目出现在多个案件时共享一份复习计划，不得生成重复卡片。

### 4.2 单章最低内容

每章目标时长为 10-15 分钟，并包含：

- 5-7 个新词汇义项。
- 3-5 个到期复习项目；没有到期项目时使用作者标记的先备复习项目补足。
- 至少一个 30-90 秒的听力场景，提供完整字幕和环境音说明。
- 至少一份 80-180 个英文单词的阅读证物。
- 至少一个需要结合英语材料作出的剧情推理。

七章合计必须覆盖信息定位、主旨、推断、说话者意图、近音辨析和搭配辨析。第七章必须在未见过的新语境中综合前六章的学习项目，不能原样重复题目。

### 4.3 诊断与冷启动

- 初始诊断覆盖词汇、听力和阅读，结果只用于选择起始难度和首批复习项目。
- 跳过诊断的用户使用标准难度，不得被标记为低掌握。
- 用户尚无真实错误历史时，只能使用作者预先审校的通用易混项。
- 同一学习项目在两个不同语境中累计两次 knowledge_incorrect，才可建立用户级易混关系。
- 用户级易混关系连续 90 天未再次出现时降低优先级，但历史事件保留。
- 没有合格陷阱变体时使用普通复习，不得动态生成未审校内容。

## 5. 七次学习会话与案件状态

“七天”是七次建议每日完成的学习会话，不是强制连续七个自然日。

- 每章完成计为一次学习会话；产品建议每天完成一章，但不设置日历硬锁。
- 漏学、跨时区或更换设备不会扣除资源、重置连续进度或触发剧情失败。
- 用户可以在同一天继续下一章；界面应提示到期复习仍按真实时间计算。
- 每宗案件的章节、检查点、案件时钟和剧情分支独立保存。
- 用户切换案件时，已到期的共享学习项目可以进入新案件的合适场景；不能自然嵌入时进入总部复盘。
- 内容更新必须保留稳定 ID。被废弃的学习项目和剧情节点停止新分配，但历史记录不得删除。

案件失败由累计三次“最差剧情选择”触发。检查点重试仅回滚检查点之后的案件状态，不回滚任何学习事件。重试必须更换题目语境；若没有合格变体，则显示解析后继续，不重复制造相同学习证据。

## 6. 输入、计时与公平性

### 6.1 答案匹配

答案匹配必须是确定性的：

1. 对输入执行 Unicode NFKC、首尾空白清理和英文字母大小写归一化。
2. 只接受内容中显式声明的 acceptedForms，不得依赖在线模型推断语义。
3. 标点和单词间多余空格可以归一化；拼写字母错误不得自动改成正确答案。
4. 中文提示必须限定目标义项和词性，避免多个合理英文答案只有一个被接受。
5. 被拒绝后必须展示目标义项、用户答案、正确形式和原因。

作者发现新的合理答案时，应更新 acceptedForms 并提升内容版本；不得追溯性改写历史结果。

### 6.2 倒计时

- 默认倒计时为 15 秒，可按词长和已证实熟练度调整到 8-20 秒。
- 用户可以随时延长或关闭倒计时；该设置不影响内容解锁、结案资格或学习评分。
- 倒计时归零可以触发最差剧情选择，但只能记录 timeout，不得记录知识错误或更新 FSRS。
- 页面失焦、应用进入后台、系统弹窗或连接中断时立即暂停倒计时。
- 倒计时归零前已经完成的有效提交必须优先处理，不能因网络响应延迟判定超时。

## 7. 剧情状态与学习证据

### 7.1 独立状态域

系统必须分别保存：

- storyState：章节、检查点、分支、案件时钟和失败次数。
- learningState：学习项目、复习计划、掌握参数和学习事件。
- attemptContext：案件、场景、题目版本、设备状态和计时信息。

任何剧情回滚不得删除或覆盖 learningState。任何学习结果也不得自动改写已经确认的剧情选择。

### 7.2 学习事件类型

每次尝试必须且只能归入以下主要结果之一：

| 结果 | 含义 | 更新 FSRS | 可影响剧情 |
| --- | --- | --- | --- |
| knowledge_correct | 在有效条件下提交正确答案 | 是 | 是 |
| knowledge_incorrect | 提交了与目标义项不符的答案 | 是 | 是 |
| timeout | 倒计时归零且没有有效提交 | 否 | 是 |
| input_cancelled | 用户取消、页面失焦或辅助操作中断 | 否 | 否 |
| system_interruption | 崩溃、断网、音频失败或同步故障 | 否 | 否 |

第一次正确且未使用提示可映射为 FSRS 的正常成功结果；使用提示后正确必须降低证据强度。knowledge_incorrect 后立即看答案再输入正确，不得制造第二次独立成功证据。具体评分映射属于共享业务规则，必须由 Vitest 覆盖。

## 8. 自适应复习与陷阱

- FSRS 调度对象是 lexemeId 和 senseId 的组合，使用真实时间而不是章节编号计算间隔。
- 到期复习优先于未到期复习，但每章复习量仍受 3-5 项上限约束；溢出项进入总部复盘。
- 陷阱只能来自内容文件中的 confusableIds，并根据用户真实的知识错误排序。
- 超时、输入取消和系统中断不得建立易混关系。
- 同一语境中的连续重试只生成一条可用于调度的知识证据，防止刷题或故障放大权重。
- 用户应能查看某项为何被安排复习，并能报告内容错误；报告行为不改变掌握度。

## 9. 内容生产与质量门槛

所有剧情、学习项目、答案、解析、字幕和内容提示必须通过 Zod 校验。结构校验之外，每章发布前还必须完成：

- 英语内容审校：语义、语法、义项、搭配和难度一致。
- 教学审校：正确答案唯一可解释，所有合理形式已进入 acceptedForms。
- 陷阱审校：错误项来源真实、区别可解释且不依赖文化刻板印象。
- 剧情审校：学习动作对剧情有意义，失败后果与线索一致。
- 无障碍审校：字幕、环境音说明、内容警告和替代交互完整。
- 试玩审校：至少三名不参与创作的目标水平学习者完成章节，阻断性歧义为零。

每个新学习项目至少提供两个不同复习语境；会进入检查点重试的项目至少提供三个不同语境。内容不足时必须采用“解析后继续”的降级路径。

## 10. 账号、隐私与数据权利

- 注册前确认用户年满 16 岁，并展示简明隐私说明和完整隐私政策入口。
- 只收集账号、学习事件、案件进度、可访问性设置和必要诊断数据。
- 不收集广告标识，不出售数据，不使用学习内容训练生成式模型。
- 产品分析使用假名化用户 ID；非必要分析必须允许用户退出。
- 用户可以导出账号、案件进度和学习记录的机器可读 JSON。
- 用户可以发起账号删除；删除请求应立即阻止继续使用，并在 30 天内删除或匿名化可识别数据。
- 日志不得记录邮箱、完整用户输入、访问令牌或可还原身份的学习文本。
- 公开测试前必须记录 Supabase 数据存储区域、跨境数据路径、备份保留期和适用合规评估；未完成时不得上线真实用户数据。

## 11. 离线与跨设备同步

- 首次登录需要联网；应用壳、当前已下载章节和必要音频应可离线使用。
- 每个学习事件使用客户端生成的唯一 eventId，服务端按 eventId 幂等写入。
- 学习事件采用只追加模型，不允许用“最后写入覆盖”合并掌握记录。
- 离线队列保留客户端时间、时区、内容版本和设备序号；服务端另外记录接收时间。
- 案件进度只允许沿已验证状态机前进；检查点重试通过显式事件表达。
- 两台设备产生冲突剧情选择时暂停该案件并让用户选择保留哪个分支。
- 学习事件仍全部合并，但同一题目版本的重复并发尝试只采用第一条有效知识证据参与调度。
- 同步失败必须保留本地队列、显示可恢复状态并支持重试。不得静默丢弃事件。

## 12. 可访问性与内容安全

目标达到 WCAG 2.2 AA，并满足以下可验证要求：

- 所有核心任务可以仅用键盘完成，焦点顺序稳定且始终可见。
- Phaser 画布中的必要地点、NPC 和证物必须提供同步的 React DOM 导航列表。
- 虚拟摇杆必须有方向按钮或目标列表替代方案。
- 所有语音提供同步字幕；关键环境音提供文字说明。
- 倒计时可以延长或关闭，页面失焦自动暂停。
- 减少动态和减少惊吓设置在进入相关场景前可用，并持久同步。
- 内容提示说明跳吓、追逐、囚禁等类别；产品不包含血腥画面。
- 自动扫描不得有严重或阻断问题，并用键盘、NVDA 或 VoiceOver 完成至少一宗案件关键路径的人工测试。

## 13. 非功能要求

- 支持最近两个主要版本的 Chrome、Edge、Firefox 和 Safari，以及 iOS 16.4 以上 Safari 和主流 Android Chrome。
- 在模拟中端移动设备和 4G 网络下，主界面 LCP 不高于 2.5 秒，INP 不高于 200 毫秒，CLS 不高于 0.1。
- 章节开始前显示资源下载大小；单章首包不超过 20 MB，音频按场景延迟加载并可清理缓存。
- 每个剧情选择和学习事件完成后立即写入本地持久队列，崩溃重启最多允许丢失当前未提交输入。
- 音频加载失败时显示字幕并允许继续；Supabase 暂时不可用时允许已下载内容离线进行。
- 客户端和服务端错误使用关联 ID 追踪，不在日志中写入敏感内容。
- 已被服务端确认的本地同步事件在 24 小时内清理；未确认事件持续保留，自动重试采用带抖动的指数退避并允许手动重试。
- 音频和场景缓存采用 LRU 清理，默认总上限为 200 MB；清理不得删除尚未完成的当前章节资源。
- 客户端诊断日志最多保留 30 天且不超过 20 MB，达到任一上限时优先删除最旧记录。
- FSRS 到期时间和服务端事件时间统一存储为 UTC；时区变化只影响显示和每日建议边界，不改写历史间隔。
- 内容清单版本变化时，已开始章节允许使用锁定版本完成；新章节必须使用当前有效版本，禁止混用节点版本。

## 14. 成功指标与发布门槛

以下为首轮封闭测试的暂定退出指标，不是对用户的提分承诺。测试至少包含 30 名完成初始诊断的目标用户；阈值调整必须写入决策日志。

### 14.1 学习有效性

- 完成七章的用户在 24-72 小时后，对已进入复习的目标义项进行未见语境测试，首次无提示正确率中位数不低于 70%。
- 对诊断中未掌握且完成规定复习的项目，延迟测试正确率相对诊断提高至少 20 个百分点。
- 100% 学习尝试可以归入已定义事件类型；timeout、input_cancelled 和 system_interruption 更新 FSRS 的次数必须为零。

### 14.2 产品体验

- 完成第一章的用户中，至少 40% 在 14 个自然日内完成同一案件七章。
- 单章有效完成时长的中位数位于 10-15 分钟，因内容歧义导致的阻断率低于 2%。
- 章节崩溃或同步失败后，可恢复进度的比例不低于 99%。
- 无障碍关键路径不存在阻断性缺陷。

样本不足时只报告观察值和置信范围，不得宣布达到学习有效性结论。

## 15. 验收矩阵

| 场景 | 输入或前置条件 | 期望结果 | 失败条件 | 验证方式 |
| --- | --- | --- | --- | --- |
| 正确作答 | 未使用提示，提交 acceptedForms 中的答案 | 记录一次正确知识证据并推进剧情 | 重复记录或匹配错误 | Vitest 和端到端测试 |
| 超时 | 倒计时归零，无有效提交 | 可推进最差剧情，只记录 timeout | 更新 FSRS 或建立易混关系 | Vitest |
| 失焦 | 倒计时中切换应用 | 立即暂停，不产生知识证据 | 自动判错 | 端到端测试 |
| 检查点重试 | 达到三次最差剧情选择 | 回滚案件状态，保留学习事件并换语境 | 删除掌握数据或重复原题 | 状态机测试 |
| 切换案件 | 两宗案件共享同一学习项目 | 案件独立、学习计划唯一 | 产生重复卡片 | 集成测试 |
| 离线学习 | 已下载章节后断网 | 本地排队，联网后幂等同步 | 丢事件或重复计分 | 端到端测试 |
| 双设备冲突 | 两台设备选择不同剧情分支 | 暂停案件并请求选择 | 静默覆盖 | 集成测试 |
| 音频失败 | 音频请求失败 | 显示字幕并允许继续 | 章节阻断 | 端到端测试 |
| 屏幕阅读器 | 不查看画布完成关键任务 | 通过 DOM 替代路径完成 | 必须像素定位 | 人工测试 |
| 删除账号 | 已登录用户发起删除 | 立即停用并进入删除流程 | 仍可登录或无反馈 | 集成测试 |
| 内容更新 | 有历史事件的项目被废弃 | 历史保留且不再新分配 | ID 复用或历史丢失 | 迁移测试 |

## 16. 发布阻断条件

出现以下任一情况时不得进入公开测试：

- 剧情状态和学习掌握度仍共享可回滚记录。
- 超时、失焦或系统故障会降低掌握度。
- 内容存在无法解释的多答案歧义或缺少字幕、解析。
- 离线事件可能静默丢失或重复影响 FSRS。

- 仅依赖 Phaser 画布才能完成核心任务。
- 未通过内容 Zod 校验、共享规则 Vitest 或关键路径端到端测试。
